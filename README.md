# Bringy: статический каталог из SQL

Сайт публикуется как обычные статические файлы. Python запускается только при сборке каталога; на хостинг отправляется содержимое `Site/`, включая `index.html`, `data.json`, `img/` и автоматически создаваемую `products/`. PostgreSQL-сервер на хостинге не нужен.

## Входные форматы

По умолчанию `python sync.py` читает `data.sql` рядом со скриптом и создаёт `Site/data.json`. Можно передать файл позиционно или через `--input`/`--dump`; кавычки позволяют использовать пути с пробелами:

```powershell
python sync.py "C:\Backups\catalog dump.sql"
python sync.py --input "C:\Backups\catalog.sql.gz" --out "Site\data.json"
```

Поддерживаются текстовые SQL-дампы PostgreSQL с `COPY ... FROM stdin` и `INSERT ... VALUES`, включая `--inserts` и `--column-inserts`, многострочные команды, схему `CREATE TABLE`, комментарии и значения с запятыми, кавычками или точкой с запятой. SQL в `.gz`, `.bz2` и `.xz` тоже читается.

Можно передать скрипт напрямую, не создавая файл. Для PowerShell:

```powershell
@'
CREATE TABLE item (name text, brand text, price numeric);
INSERT INTO item VALUES ('Boots', 'Brand', 50);
'@ | python sync.py --stdin
```

Также работает обычный конвейер `Get-Content script.sql | python sync.py --stdin` и короткая форма `type script.sql | python sync.py -`.

Для custom/directory-архива PostgreSQL (`pg_dump -Fc`/`-Fd`) скрипт использует `pg_restore`, если он установлен локально. Если нет, сначала преобразуйте архив в текстовый SQL. Это локальная зависимость только для чтения таких архивов.

Если `INSERT INTO item VALUES (...)` не содержит имён колонок, они берутся из `CREATE TABLE`. Для data-only дампа без схемы укажите их вручную или создайте дамп с `--column-inserts`:

```powershell
python sync.py data-only.sql --columns "item=id,name,brand,price,image,sizes,color,available,sex"
```

Скрипт извлекает табличные данные, а не исполняет произвольный SQL-код или процедуры. Для каталогов без распознаваемых таблиц он завершится с ошибкой и не заменит предыдущий JSON пустым файлом.

При каждой сборке для товаров выбранной таблицы создаются отдельные статические страницы в `Site/products/`. Каталог автоматически связывает карточку с её страницей. Добавьте товар в SQL и снова выполните `python sync.py`; новая страница и обновлённые ссылки появятся при следующей публикации содержимого `Site/`.

Между сборками товары сопоставляются по изображению, полу (`sex`) и бренду без учёта регистра и вида разделителей в пути изображения. Совпавший товар обновляется новыми полями, новый добавляется, а отсутствующий во входном SQL сохраняется. Чтобы удалить товар, удалите его также из `Site/data.json` перед сборкой.

## Просмотр и публикация

Для локального предпросмотра можно запустить `python sync.py --serve 8000` и открыть `http://localhost:8000`. Это только локальная проверка; рабочий сайт остаётся статическим.

Загрузите **содержимое папки `Site/`** на любой статический хостинг. Для обновления каталога замените SQL, снова выполните `python sync.py` и опубликуйте новый `Site/data.json`.
